# 验证记录

日期：2026-09-10。环境：Linux 主机，GCC 11.4.0、Python 3.10.12。基于原仓库提交 `53ff95406c1d082ca1cff834db0c7d4119d311fc` 的新增工程。以下区分软件检查、合成仿真与历史数据回放，不将其中任何一项称为实车认证。

## 构建与回归

执行命令：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_FLAGS='-Wall -Wextra -Werror -pedantic'
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/power_control_demo
```

结果：C99 严格警告构建通过，CTest 三项全部通过。

| 检查 | 结果 | 覆盖范围 |
| --- | --- | --- |
| `power_control` | 13,859 checks，0 failures | 解析解、非单调制动、非法输入、不可行预算、限流、400 个确定性随机场景、能量预算与反馈降级 |
| `model_fitting` | 6 项 Python 测试通过 | 三类模型系数恢复、非负边界、激励不足、旧 CSV 对齐、独立验证与头文件生成、重复验证路径拒绝 |
| `dynamic_simulation` | 28,000 个两轨迹合计控制步通过 | 动态数值、输出符号/幅度、模型约束、能量范围与失联状态覆盖 |
| C 头文件导出 | 严格 C99 编译检查通过 | 生成的模型结构可由公共 API 使用，不代表参数可部署 |

另以 `-DNDEBUG -fsanitize=address,undefined -fno-omit-frame-pointer` 编译并运行 C 数值回归，13,859 项检查通过。环境不支持 LeakSanitizer，执行时设置 `ASAN_OPTIONS=detect_leaks=0`，地址与未定义行为检查保持启用。Release 下测试使用独立检查宏，不会被 `NDEBUG` 去掉。

已配置 GCC/Clang GitHub Actions 工作流；本记录只声明上述本地执行结果，不将尚未运行的远端 CI 算作通过。

示例中的 NORMAL / CHARGE / BOOST 预算分别为 75 / 60 / 125 W，返回预测功率分别为 75 / 60 / 110.518 W。制动案例在 2 W 预算下得到 `scale=0.816228`；无可行解案例预算 1 W、最低预测消耗 2 W，正确置位 `INFEASIBLE`。

## 动态仿真结果

完整工况和方程见 [仿真说明](../simulations/README.md)。两套系统各模拟 28 s，步长 2 ms，具有独立速度与储能状态；控制器模型有意低估真实 plant 参数约 8% 至 11%。基线仍执行电流限制，只是不执行功率预算。

| 指标 | 仅限流基线 | 启用功率控制 |
| --- | ---: | ---: |
| 四轮速度跟踪 RMSE / rpm | 57.690 | 117.011 |
| 电机侧真实功率高于自身预算的峰值 / W | 224.685 | 13.587 |
| 电池侧真实功率高于供电阈值的峰值 / W | 155.528 | 3.587 |
| 电池侧超阈值功率的时间积分 / J | 846.589 | 2.233 |

功率抑制明显，同时速度跟踪付出代价。两条轨迹储能不同，电机侧预算也可能不同，因此“各自预算超调”不是同一固定阈值的比较；电池侧指标使用对应时刻的共同供电阈值。

该结果仍出现真实超限，不能宣称“永不超功率”。回归通过表示设定的数值不变量满足，不能把拟合模型的预算保证扩展成实际硬件功率保证。功率下降也包含速度变慢带来的机械做功下降，不表示效率按同等比例提高。

![合成动态仿真功率、跟踪与储能对比](assets/power_control_sim.png)

运行结果的 CSV、SVG 和完整指标在本地 `artifacts/simulation/`；仓库保存主图和 [生成报告](simulation-report.md)。原始 CSV 由确定性程序再生成，不额外提交数万行数据。

## 原仓库数据回放

采用 [标定文档](calibration.md) 中的命令，训练文件为 `ramp.csv`、`ramp2.csv`，验证文件为 `sin.csv`、`test1.csv`。按历史脚本假设母线电压 24.56 V，固定机械系数 `1.99688994e-6`，拟合二次转速、铜损和空载项。

| 数据划分 | 有效行数 | RMSE / W | MAE / W | 最大绝对误差 / W |
| --- | ---: | ---: | ---: | ---: |
| 训练 | 74,622 | 9.9341 | 5.4843 | 45.8396 |
| 验证 | 23,346 | 3.4536 | 3.3063 | 8.1113 |

该组假设下，损耗参数全部落到零边界，**不接受其作为可部署的电机标定**。这不证明原历史工作无效，只说明当前 CSV 与假设不足以重建可靠的损耗模型；还需核查采集条件、传感器标度、符号和同步。拟合工具保留该诊断，未人为修改结果以获得好看的参数。
